# NetProxy-NoTelemetry

NetProxy（Magisk / KernelSU / APatch 模块）的**去统计版**自动构建。

> **非官方项目。** 本仓库与 NetProxy 作者无关，不包含任何原创功能，只是自动从官方仓库
> [Fanju6/NetProxy-Magisk](https://github.com/Fanju6/NetProxy-Magisk) 同步发布，
> 并在官方安装包的基础上去掉设备统计代码。功能问题、使用方法和更新日志请以官方仓库为准。

## 这是什么

官方安装包里的 `netproxyctl` 带有设备统计功能（统计日活和核心启动结果，并附带设备信息）。
本仓库的工作流会在官方发布新版本后，用官方对应版本的源码重新编译一份不带统计代码的 `netproxyctl`，
替换进官方安装包后发布到这里的 Releases。

## 和官方包的区别

只有下面两处，其余文件与官方包完全一致：

1. **`bin/netproxyctl`**：用官方同一版本的源码重新编译，编译前删除了统计代码（`internal/telemetry` 及其所有调用点）。
   编译时不注入任何统计密钥，并在构建时检查产物里没有统计相关的函数、地址和密钥，有就让构建失败。
2. **`customize.sh`**：去掉了为统计创建锁文件的两行。统计代码已删除，这个锁没有用处。

`module.prop`、WebUI、管理器 APK、sing-box 内核、规则文件等都原样保留，模块名称和版本号也与官方相同，
可以直接覆盖安装官方版，反过来也可以。

## 下载

在 [Releases](../../releases) 里下载：

| 类型 | tag | 说明 |
|---|---|---|
| 正式版 | `v8.7.1` 这样的版本号 | 与官方正式版一一对应，标题带"（去统计）" |
| 每夜版 | `nightly` | 对应官方 `nightly` 预发布，标记为预发布，随官方更新而重建 |

安装包文件名在官方文件名的 `NetProxy_` 后面加了 `notelemetry_`，
例如官方的 `NetProxy_v8.7.1_1107.zip` 对应这里的 `NetProxy_notelemetry_v8.7.1_1107.zip`。
每个 release 的说明里写明了基于哪个官方版本、哪个源码提交，并附上官方的更新日志原文。

## 自动同步

工作流 [`auto-notelemetry.yml`](.github/workflows/auto-notelemetry.yml) 每天北京时间 00:00 运行一次：

1. 从官方仓库取最新正式版和 `nightly` 的安装包与更新日志。
2. 读出该安装包对应的源码提交，下载同一提交的源码。
3. 删除统计代码并编译，检查产物。
4. 替换安装包里的 `bin/netproxyctl` 并发布；已经处理过的版本会跳过。

也可以在 Actions 页面手动运行：

- **重新构建已处理过的版本**：勾选后会先删除同名 release 再重建。
- **指定要构建的版本号**：填 `v8.6.2` 这样的版本号，只构建这一个版本；留空则自动构建最新正式版和每夜版。

## 注意

- 官方在版本更新里改动统计代码的位置时，整体删除可能对不上，工作流会自动退回到"保留空实现"的方式，
  并在构建日志里给出警告。此时统计功能同样不会运行，但二进制里会残留少量无用代码。
- 模块的 `updateJson` 仍指向官方仓库，模块管理器检查更新时会访问官方的 `update.json`，
  这是更新检查，不是统计，也可能提示官方有新版本。需要更新时请以本仓库 Releases 为准。
- 以前安装过官方版的设备上，`/data/adb/modules/netproxy/config/telemetry/` 下可能还留着旧的统计队列文件，
  新版不会再读取它，可以手动删除。
- 本仓库的发布没有经过官方审核或认可。使用中遇到问题，建议先确认官方版是否同样出现，再决定去哪里反馈。
